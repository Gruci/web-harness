# docs/BACKLOG.md — 잔여 백로그

> 담는 것: 아직 착수하지 않은 일과 그 판단 근거. 담지 않는 것: 지금 누가 무엇을 잡고 있나와 착수~완료 절차(→ `workboard/README.md`)·세션 행동 규칙(→ `CLAUDE.md`). 읽는 시점: 다음 과업을 고를 때.

> **진행 중 과업은 여기 없다.** `workboard/` 가 그 자리다 — 파일 하나가 과업 하나이고
> git 에 추적되지 않는다. 이 파일은 **남은 일**만 쥔다.

> **열린 것만 남긴다.** 완료·기각 행은 지운다 — 경위는 git 이력과 `docs/tasks/archive/`에 있고, 여기 쌓이면 "지금 뭐가 남았나"를 못 읽는다.
> ⚠️ **착수 전에 서술을 실물로 대조한다.** 원류 정리에서 8건 중 5건이 "착수해보니 이미 해결돼 있었다"였고 3건은 전제가 통째로 낡아 있었다. 백로그는 **관측이 아니라 기억**이다.

> 📦 **이 파일은 프로젝트를 따라간다.** `PROJECT.md` 와 같이 **새 프로젝트가 채우는 문서**다 — 하네스를 clone 해 가면 이 파일도 따라가서 그 프로젝트의 잔여 작업을 담는다. 그래서 배포본은 비어 있는 것이 정상이다. 하네스를 만들며 생긴 메모를 여기 남기면 **그 메모가 모든 새 프로젝트로 배송된다.** 하네스 자신의 설계 판정은 `dev/REJECTED.md` 가 받는다.
